# Project Summary: MetaTrader 5 Quant Server

This project is a comprehensive, Docker-based platform for quantitative trading that integrates with MetaTrader 5 (MT5). It provides a full-stack solution including a backend server, a connection to the MT5 terminal, and a complete monitoring suite.

## Core Components

The project is composed of several key services, orchestrated using Docker Compose:

### 1. Backend

The backend is a Django application responsible for the core logic of the trading platform. It includes:
- **`quant` app:** Contains the quantitative trading algorithms, indicators, and task management.
- **`nexus` app:** Likely provides API endpoints and manages data.
- **Celery:** Used for running background tasks and scheduled operations, such as executing trading algorithms.
- **PostgreSQL:** The primary database for the Django application.
- **Redis:** Used as a message broker for Celery and for caching.

### 2. MetaTrader 5 Integration

A key feature of this project is its ability to interact with the MetaTrader 5 terminal. This is achieved through a dedicated service that includes:
- **MT5 on Wine:** The MT5 terminal runs on a Debian-based Docker container using Wine.
- **Flask API:** A Python Flask application provides an API to interact with the MT5 terminal. This allows other services to send and receive data, execute orders, and manage positions.
- **VNC Access:** Remote desktop access to the MT5 application is provided via a web-based VNC client.

### 3. Reverse Proxy and Security

- **Traefik:** Acts as a reverse proxy for all web-facing services. It handles routing, SSL termination, and provides a dashboard for monitoring traffic.
- **Let's Encrypt:** Traefik is configured to automatically obtain and renew SSL certificates from Let's Encrypt, ensuring secure communication.

### 4. Monitoring and Logging

The project includes a robust monitoring and logging stack to ensure reliability and performance:
- **Grafana:** For visualizing metrics and logs in dashboards.
- **Prometheus:** Collects metrics from various services, including the host system and Docker containers.
- **Loki:** A log aggregation system that collects logs from all services.
- **Promtail:** An agent that ships logs from Docker containers to Loki.
- **Alertmanager:** Handles alerts generated by Prometheus and can be configured to send notifications.
- **cAdvisor & Node Exporter:** Provide detailed metrics about container and host system performance.

## Architecture Overview

The services are interconnected as follows:
- **Traefik** is the entry point for all HTTP/HTTPS traffic, routing requests to the appropriate services (Django, Grafana, VNC, MT5 API).
- The **Django** application serves as the main backend, managing trading logic, data, and user interactions.
- Django communicates with the **MT5 service** via its Flask API to execute trading operations on the MetaTrader 5 terminal.
- **Celery workers** handle asynchronous tasks, such as running trading strategies, managed via messages from **Redis**.
- The **monitoring stack** (Prometheus, Grafana, Loki) collects and displays data from all services, providing a comprehensive overview of the system's health and performance.

This project provides a powerful and scalable foundation for developing and deploying automated trading strategies using MetaTrader 5.
